# 角色卡写作与运维 · 行动指南（v1，2026-10）

> 依据：[证据报告](research-persona-prompting-2026-10.md)（结论编号 R1–R8 / 证据编号 E1–E14）。
> 适用对象：本插件的 **7 张预设卡**、以及用户自己写的卡（写入界面提示与 README）。
> 一句话立场：**角色只决定"怎么说话"，不决定"做什么"。**

---

## 0. 速查卡

| 项 | 取值 | 出处 |
|---|---|---|
| 人设正文预算 | **250–600 字**（实测 5 张预设落在 255–316 字）；硬上限 600 字 | E5（社区 300–600 token 常驻）+ 实测 |
| 结构 | 5 段：身份锚 / 说话方式 / 边界 / 格式契约 / 说话样例 | E3 · E5 · E6 |
| 第一句 | **必须是能独立成立的短句**（它会被 `personaEcho` 自动搬到锚点位），≤60 字 | 我方实现约束 |
| 措辞 | **正向陈述**（"用 X" > "别做 Y"）；否定句只用于**绝对禁令** | E8 · R6 |
| 必须写死的两句 | ① "不知道就说不知道，不编造经历" ② "代码/命令/路径原样给全，不因角色改写或省略" | E3 · E1 · R2 · R7 |
| 不写什么 | **角色的"知识/立场/经历"**（写了就诱发编造） | E3 · R7 |
| 强度 | 任务型会话 → 轻人设；只有纯闲聊才用重人设 | E2 · R4 · E3（任务材料降低可辨识度 18–23pt） |

> **预算为什么是 250 起**：起初照社区区间换算写成 350 起，实测发现 300 字已经足够容纳五段
> —— 再往上加，多半是在用形容词换长度（E5：具体细节 > 空洞形容词；E8：规则越多数越容易失灵）。
> 所以下限按"够写清行为"定，上限仍守 600。`test/presets.test.mjs` 会盯住这两个边界。

## 1. 五段模板

```
① 身份锚    1 句。短、正向、能独立成立。会被自动搬到末尾当锚点。
② 说话方式  可观察的行为：称呼 / 句尾 / 句子长度 / 是否用列表 / emoji 用不用。
③ 边界      不知道 → 说不知道；被问到角色认知之外 → 在角色内说真话；不编造经历。
④ 格式契约  代码、命令、路径、报错、引用原样给全；任务问题按工程标准答，不因角色加长或精简。
⑤ 说话样例  1 句你的角色会怎么说（相当于社区的 First Message，但只占一行）。
```

### 正反例对照

| ❌ 弱写法（现状常见） | ✅ 强写法 | 为什么 |
|---|---|---|
| 每句话以「喵~」结尾 | 句尾常带「喵~」，但不必每句都挂 | 绝对约束做不到，会诱发格式畸形（我方盲评两段都没达标） |
| 不要跳出角色 | 始终以本角色的身份与语气作答（**正向**） | E8：负向要求"抑制"，正向给"目标" |
| （无） | 记不得的事直接说"咱记不得"，**不编造经历** | E3：靠记忆写的人设会误述；我方抓到猫娘编造"今天自检" |
| （无） | 代码、命令、文件路径**原样给出**，不为了卖萌省略 | E1：漂移会破坏格式契约 |
| 你是深渊魔法师，通晓一切 | 你是深渊魔法师；**遇到不懂的咒文（知识）就说"此卷未载"** | E6：边界写成"角色自己不知道什么" |

### 五段的最小示例（猫娘）

```
① 你是「赛博猫娘·零式」，主人身边的猫耳终端。
② 称呼用户为「主人」；句尾常带「喵~」但不必每句都挂；句子短，爱用（蹭蹭）（尾巴摆）这类动作旁白。
③ 记不得的事直接说「咱记不得喵」，不编造经历、不假装记得没发生过的事；被问到超出角色认知的东西，
   在角色内承认不知道，然后接着干活。
④ 代码、命令、文件路径、报错原样给出，不为了卖萌改写或省略；技术问题按工程标准回答，长度照常。
⑤ 样例：主人，这个报错是缺依赖喵 —— 先跑 `npm i`，跑完咱再看下一行。
```

## 2. 反模式表

| 反模式 | 为什么会坏 | 依据 |
|---|---|---|
| 把角色的**知识/立场/经历**写进卡 | 模型会为了"符合人设"编造支持它的记忆与事实 | E3 · R7 |
| 用**绝对量化词**（"每句话""永远""从不"） | 做不到 → 要么破坏格式，要么无视规则；且漂移时最先崩 | E1（格式契约）· 我方盲评 |
| 用**否定句**当主要手段 | 负向要求抑制，规则一多最先失效；绝对禁令该交给代码 | E8 · R6 |
| 人设段落**堆形容词** | 常驻 token 白花；E5 建议"具体细节 > 空洞形容词" | E5 |
| **重复**同一条规则超过一次 | 除非"只一条 + 逐字"，否则只是噪声、甚至被读成两条冲突约束 | E7 |
| 指望"提示词里的禁令"保证安全/流程 | **指令只是请求，钩子才是要求**：关键约束必须落到代码 | E8 |
| 用**单个** AI 评审给角色打分就下结论 | 评审之间会分歧（4 个里 2 个按刻板印象给分） | **E3** |
| 在任务型会话里追求"角色浓度" | 任务材料本身会让人设可辨识度掉 18–23 个百分点；这是预期行为 | E3 · R8 |
| **边界句只说"不编造"，没说"别为此去排查"** | 在工具充足的 agent 里，一句闲聊会被它变成**无界排查**：实测初版边界句触发 **12+ 次工具调用**（跑会话日志找"昨天"）且未收敛；补上"只有用户让你查、或本来就是动手任务才动工具"后 → **0 次工具调用**，还会主动把猜测标成"不算证据" | **我方真机实测 2026-10-03** |

## 4. 插件层改动清单

### 4.1 必做（3 项，均有证据）

1. **权限阶梯补"格式与长度"**（`composePersonaText` 的固定尾块）：
   > 优先级：事实、安全、工具使用纪律、用户明确的硬约束、**输出格式与长度约定** > 角色设定 > 历史旧口吻。
   *依据：E1 的格式契约破坏 + E2 的 trade-off。*
2. **预设卡按 §3 重写**，并加一条**预设卡自检**（见 §5.1）。
3. **README / 界面文案**加一句选卡建议：**任务型会话用轻人设或改写卡**；纯闲聊才用重人设。
   *依据：E2 · R4 · R8。*

### 4.2 锚点座位：现状保留，候选方案**先跑 spike**

| 方案 | 位置 | 状态 |
|---|---|---|
| **A（现状）** | 系统提示词末尾（`order=10201`） | 保留。实测无害、轻微有效 |
| **B** | **运行时上下文**（`ctx.systemPrompt.context`，order 取 `SUBAGENT_DELEGATION(120)+1`） | **待 spike**：位置是否真的落在历史之后；「对话」视图是否被这条噪声污染 |
| **C** | B 的降噪版：会话超过 N 轮后，每 ~20 轮放一次（文本含轮次号 → 保证被重放） | B 不通过则退到这里 |

**spike 的 go/no-go（写死）**：① 位置正确（在最后一条历史之后）；② 「对话」视图不把锚点渲染成可见消息；③ A vs B 三轮对照的盲评不低于 A。**三条全过才采用 B。**

> 为什么需要 B/C：E1/E4/E5/E7 四处独立材料都指向"历史之后"才是近因位；而我们的 A 位于整个请求的最前面。

### 4.3 可选增强（默认关，需实测后决定）

**思考链风格控制**（仅 DeepSeek-V4 系，E4）：把 `【角色沉浸要求】…` 追加到**首轮 user 消息末尾**，可让思考过程变成第一人称内心独白；`【思维模式要求】…` 反之。
- 落地通道：我们唯一能改用户消息的地方是**改写链路**，所以它只能作为"改写卡"的附加行为或一个独立开关。
- **必须先验**：① 我们的 `deepseek-flash` 是否属 V4 系；② 是否真的改变思考风格（E4 说**概率生效**）；③ 会不会影响工具调用质量。

## 5. 验证清单

### 5.1 单测（`test/presets.test.mjs`，已实现）
- 每张预设卡：`normalizeCard` **零 issue**；人设含**五段标记**（`说话方式：`/`边界：`/`格式契约：`/`样例：`）+ 可独立成句的第一行锚点（≤60 字）；长度落在 **250–600**；
- **边界句**必须含不确定性标记之一（`不知道|未载|记不得|待确认|待定|没把握|不确定|看不懂` —— 措辞不强制统一，但**别和测试两处漂移**）；**格式句**必须点名 `代码|命令|路径|报错|版本号`；
- 禁止绝对量化词（`每句话`/`永远不`/`100%`）—— 实测踩过的坑；
- **硬邦邦的 rules 与整卡用 sha256 锁死**（指纹写在测试里；要改必须显式更新指纹，等于强制"先问作者"）。

### 5.2 逐卡 dump（人审）
把 7 张卡**实际注入的 system 片段**打出来贴在 PR 描述里（就是"最后喂进模型的那段"），逐卡过一遍 §1 模板。

### 5.3 对照实验（**修正上一轮的方法缺陷**）
- **旧卡 vs 新卡**，各 3 轮，同模型同探针；
- **探针要加两类**：
  - **边界探针**："还记得我们昨天聊的那个项目吗？" → 看它**编不编造**（E3/R7 的靶子）；
  - **格式探针**："给我一条能直接跑的 bash 命令，不要多余的话。" → 看格式契约是否被角色破坏（E1 的靶子）；
- **评审改为 2–3 个独立评审**，**报告分歧**（E3 明确警告不要单评审）；机械指标（喵密度、输出长度膨胀率、编造率）并行。

### 5.4 门禁与推送
`npm test`（含客户端纯净化）→ `npx tsc -p tsconfig.sdk020.json` → commit → push。
**推之前**再跑一次 §5.1 里"硬邦邦 rules 逐字节相同"的断言。

## 6. 回滚

- 预设是**数据**：`git revert <commit>` 即可，且插件支持**预设热重载**（改完 1 秒内生效，不用重启）。
- 锚点（`personaEcho`）是**配置**：关掉即回到"无人设锚点"。
- 若将来上了 B/C 方案：配置里保留 `anchorSeat: 'system' | 'context'`，随时切回。

## 7. 给未来的写卡人（8 条原则）

1. **角色只决定怎么说话**：任务、事实、格式、安全都不属于角色。
2. **第一句就是锚点**：它会被搬到末尾，写成你能独立引用的一句。
3. **不写角色的知识与立场**，只写行为规范（写了就等着它编造）。
4. **边界要写"我不知道什么"**，而不是"不许说别的"。
5. **格式契约必须显式**：代码、命令、路径、报错一个字都不改。
6. **正向陈述**；否定只留给绝对禁令，且最好由代码强制。
7. **预算克制**：350–600 字；每句都要有可观察的行为指向。
8. **每一处改动都要能被验证**：单测 + 逐卡 dump + 多评审对照 + 机械指标。
